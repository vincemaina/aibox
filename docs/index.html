The problem

An agent with your shell has your whole machine

Coding agents are most useful when they can run commands. But the same shell that runs your test suite can read ~/.ssh/id_ed25519, query your warehouse with your dbt profile, or push to main. Most sandboxes fix this by taking away the tools that make the agent useful. aibox draws the line somewhere better: the agent gets a full development environment and your real project files, and none of your identity.

What you get

Features

Credential isolation

Your home directory is never mounted. No SSH keys, cloud credentials, dbt profiles, or ~/.gitconfig. The container sees your project and four of its own volumes — nothing else.

Real Git, no remotes

The agent reads history, commits, and branches, so its work arrives as a reviewable sequence rather than one undifferentiated diff. It can't push: there's no gh and no credentials.

--git commit is the default. readonly and masked tighten it.

No route back to the host

The Docker socket is never mounted. .git/hooks and .git/config stay read-only in every mode, so the agent can't leave behind a hook or a core.pager that your Git would run later.

Browser testing built in

Chromium's system libraries are in the image. An agent installs Playwright, drives a headless browser, screenshots the page and reads the PNG back — so it can check its own UI work instead of guessing.

Agents arrive oriented

Every box seeds a briefing the agent reads as memory: you're in a container, this isn't the user's machine, here's why git push and ~/.ssh aren't available — and a hard rule never to work around a protection or touch anything outside the mount.

Templates for your practices

Keep your CLAUDE.md, working practices, and skills in one template repo. aibox init merges them into a project without overwriting anything, and personal skills can load into the container instead of your repo.

Disposable, but not forgetful

The container is removed on exit. /home/dev, /tmp, /var/tmp and /opt are per-project volumes, so npm globals, shell history and agent config survive.

Owned by you, not root

The container user is retuned to your host UID and GID at startup, so files the agent creates in your project belong to you. No sudo chown afterwards.

Nothing to install but the CLI

Pure Python standard library, shelling out to the docker CLI. No SDKs, no daemon, no account. Roughly a thousand lines you can read in an afternoon.

Getting started

Up and running

You need Docker running and Python 3.11 or newer.

Install the CLI

pipx keeps it in its own environment and puts aibox on your PATH.

$ pipx install git+https://github.com/vincemaina/aibox.git

Start a box in any project

First run builds the image. After that it starts in about a second.

$ cd ~/projects/my-app
$ aibox

Run your agent inside it

You're at a shell in /workspace as a non-root user. Install the agent once — it persists on the project's home volume.

$ npm install -g @anthropic-ai/claude-code
$ claude

Questions

Common questions

Can the agent see my SSH keys or cloud credentials?

No. Your home directory is never mounted. The container sees your project at /workspace plus four project-specific Docker volumes, so ~/.ssh, ~/.aws, dbt profiles and GitHub tokens are simply not reachable from inside.

Can the agent commit to my repository?

Yes, and that's the default. It can read history, commit, branch and rebase, so it can arrange its work into a history you can review. It cannot push — there are no credentials and no GitHub CLI in the container. Protecting shared history is the remote's job, via branch protection rules.

Can the agent break out of the container?

The Docker socket is never mounted, so it can't talk to the daemon that runs it. It runs as a non-root user. And the two Git paths that would cause code to run on your machine later — .git/hooks and .git/config — are held read-only in every mode, including when the agent is allowed to commit.

Does it work on Linux, macOS and Windows?

Yes. On Linux, Docker Engine needs your user in the docker group, and an entrypoint script matches the container user to your host UID and GID so files stay owned by you. On Windows use Docker Desktop or WSL2. Podman is not supported yet.

Can an agent test the web app it just built?

Yes. Chromium's system libraries ship in the image — the part that needs root and so can't be installed from inside. The agent installs Playwright, screenshots the page into /workspace, and reads the image back. No GUI is involved; agents see by reading image files.

Is this just docker run with extra steps?

It's the specific set of flags you'd otherwise get wrong. Stable per-project identity and volumes, host UID matching, terminal colour passthrough, and the Git protections above. You could write the command by hand; you'd write it differently in every project.
